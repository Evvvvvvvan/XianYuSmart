### 正文

**先说结论**：这个版本没有新功能，只有一堆"平时看不出来、出事就是钱"的修复。如果你在用自动发货或多账号托管，建议尽快升级。

#### 这些 Bug 为什么平时发现不了

闲鱼托管这类系统的状态特别多：订单要经历"待付款→待发货→已发货→已完成"，卡密要经历"可用→预占→已交付"，私聊消息还有自己的一套"待发→发送中→已发"。

这些状态在我们代码里，过去是用一个个数字字段和布尔变量拼出来的——没有统一的状态机，也就没有"什么状态能变成什么状态"的强制约束。于是就出现了这样的场景：

- 一个发货任务卡了 2 分钟，调度器以为它挂了，派另一个实例去接手。原来的实例这时候又"醒来"把结果写回去了——**同一张卡密被发了两次**。
- 平台偶尔返回一个 500，代码把它当成"Cookie 过期"，而这个状态是所有接口的硬门禁，**账号直接从列表里消失**，只能手动重新登录。
- 保存发货配置时，代码里写死了一个"自动确认发货 = 开"，**用户没点过的开关被悄悄打开**。

这次我们把它们逐条挖出来，全部改成"带守卫的状态迁移"：每次改状态，都必须同时满足"当前状态正确"和"这个任务确实归我处理"，否则直接放弃这次写入。

#### 你会感受到的变化

**1. 不会再重复发货**
发货任务、发货私聊、运营任务、自动回复四条链路都加了租约归属校验。超时重试、多实例并发、进程卡顿，都不会再让同一份卡密发两遍。

**2. 账号不会莫名消失**
平台返回 500 属于瞬时故障，不再被判定成"Cookie 失效"。只有明确的 401 和过期信号才会触发；需要验证的账号也会正常显示成「需要验证」，而不是一行「未知」。

**3. 配置不会被悄悄改写**
保存发货配置不会再强制打开「自动确认发货」。该开关只由它自己的按钮控制。

**4. 商品状态更可靠**
商品列表同步时如果某一页请求失败，不会再拿"不完整的列表"去比对，把没拉到的那几页商品全标成"已删除"。

**5. 登录安全**
之前登录失败计数会被反复重置，等于**永远锁不住**。现在连续失败 5 次会真正进入 10 分钟锁定。

**6. 前端更"听话"**
待处理订单的自动发货定时器不会叠加触发；扫码登录成功后会立刻停止轮询，不会重复建号；商品同步失败后刷新按钮不会一直灰着；上传图片失败也不会留下后台定时器。

#### 升级方式

**方式一：替换 JAR（推荐，最快）**

```bash
# 1. 备份数据库与旧版本
docker compose exec mysql mysqldump -uxianyusmart -p xianyusmart > backup-$(date +%F).sql
cp /opt/xianyuSmart/app.jar /opt/xianyuSmart/app.jar.bak

# 2. 替换并重启
cp xianyusmart-2.1.2.jar /opt/xianyuSmart/app.jar
docker compose -f /opt/xianyuSmart/compose.yaml restart app
```

**方式二：Docker 镜像**

```bash
docker pull ghcr.io/evvvvvvvan/xianyusmart:v2.1.2
export APP_IMAGE=ghcr.io/evvvvvvvan/xianyusmart:v2.1.2
docker compose up -d
```

> 注意：本次新增数据库迁移 `V19`（给运营任务加租约字段），首次启动会自动执行，请务必先备份。

#### 已知限制

- 多副本部署时，连接状态、风控熔断、人工接管缓存仍是进程内状态，扩容前需要额外的共享存储方案。
- 平台消息发送超时目前仍按"已发送"处理（否则会重复发送），下一版会拆出"已发送但未确认"的独立状态。
