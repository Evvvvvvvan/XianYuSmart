# XianYuSmart v2.1.2 微信发布文案

## 一、群公告版（对齐 v2.1.1 排版）

【v2.1.2｜堵住重复发货窗口，账号不再莫名掉线】本次更新是一次"状态机加固"：把发货、回复、运营任务里那些平时看不出来、出错就要赔钱的隐患，逐个改成带守卫的状态迁移。没有新功能，但建议所有在用自动发货的用户升级。

本次正式发布新增及修复：

【履约可靠性】
• 发货任务引入"租约归属"：任务卡住被另一个实例接手后，原来的执行者不能再写回结果，同一张卡密不会因超时重试被发两遍
• 发货私聊只有在"发送中"状态才能标记为已发送，堵住超时重发与并发发送互相覆盖的窗口
• 自动回复的成功/失败写入按状态守卫拆分：旧任务不会再把已经完成的回复覆盖成失败，也不会重复回复
• 重连补推的旧消息按（账号＋会话＋消息ID）去重，不会再把正在等待的回复静默取消
• 商家运营任务（发布、下架、补偿等）同样加租约：双实例运行不会重复发布同一件商品

【账号与凭证】
• 平台偶发 500 不再被判定为 Cookie 过期（只认 401 与明确的过期信号），账号不会莫名从列表消失
• 需要验证的账号现在正常显示"需要验证"，不再是"未知"
• 登录失败 5 次真正触发 10 分钟锁定：此前计数会被反复重置，等于锁不住
• Token 刷新成功、人工重启后会清理重连与滑块退避状态，避免零延迟重连风暴；自动重连不再被清空退避
• WebSocket 停止与启动共用账号锁，心跳线程不会再误关刚建立的新连接

【数据与配置】
• 保存发货配置不再强制打开"自动确认发货"，该开关只由它自己的按钮控制
• 商品列表同步时若分页未拉完，不再把没拉到的商品误标为"已删除"
• 外部供货的卡密预占现在可以正常释放，仓库不会被永久锁死、无法编辑
• 收货后话术的进度更新失败时跳过本轮，避免同一条话术重复发送
• 外部卡密请求的重试不再作废人工确认记录

【前端体验】
• 待处理订单的自动发货单飞执行，定时器不会叠加触发
• 扫码登录成功后立刻停止轮询，不会重复创建账号
• 商品同步失败后刷新按钮不再一直灰着
• 图片上传失败不再遗留后台定时器；切换账号时连接状态不再串号
• 修改向导跳转不再丢校验，回复开关切换失败会回到原状态

⚠️ 升级提醒
本次包含数据库迁移 V19（运营任务增加租约字段），首次启动自动执行，**升级前请先备份数据库**。
替换 JAR 或拉取新镜像后重启应用，并强制刷新一次页面（Ctrl/Cmd + Shift + R）。
多副本部署仍需注意：连接状态、风控熔断、人工接管缓存目前是进程内状态。

### 正文

**先说结论**：这个版本没有新功能，只有一堆"平时看不出来、出事就是钱"的修复。如果你在用自动发货或多账号托管，建议尽快升级。

#### 这些 Bug 为什么平时发现不了

闲鱼托管这类系统的状态特别多：订单要经历"待付款→待发货→已发货→已完成"，卡密要经历"可用→预占→已交付"，私聊消息还有自己的一套"待发→发送中→已发"。

这些状态在我们代码里，过去是用一个个数字字段和布尔变量拼出来的——没有统一的状态机，也就没有"什么状态能变成什么状态"的强制约束。于是就出现了这样的场景：

- 一个发货任务卡了 2 分钟，调度器以为它挂了，派另一个实例去接手。原来的实例这时候又"醒来"把结果写回去了——**同一张卡密被发了两次**。
- 平台偶尔返回一个 500，代码把它当成"Cookie 过期"，而这个状态是所有接口的硬门禁，**账号直接从列表里消失**，只能手动重新登录。
- 保存发货配置时，代码里写死了一个"自动确认发货 = 开"，**用户没点过的开关被悄悄打开**。

这次我们把它们逐条挖出来，全部改成"带守卫的状态迁移"：每次改状态，都必须同时满足"当前状态正确"和"这个任务确实归我处理"，否则直接放弃这次写入。

#### 你会感受到的变化

**1. 不会再重复发货**
发货任务、发货私聊、运营任务、自动回复四条链路都加了租约归属校验。超时重试、多实例并发、进程卡顿，都不会再让同一份卡密发两遍。

**2. 账号不会莫名消失**
平台返回 500 属于瞬时故障，不再被判定成"Cookie 失效"。只有明确的 401 和过期信号才会触发；需要验证的账号也会正常显示成「需要验证」，而不是一行「未知」。

**3. 配置不会被悄悄改写**
保存发货配置不会再强制打开「自动确认发货」。该开关只由它自己的按钮控制。

**4. 商品状态更可靠**
商品列表同步时如果某一页请求失败，不会再拿"不完整的列表"去比对，把没拉到的那几页商品全标成"已删除"。

**5. 登录安全**
之前登录失败计数会被反复重置，等于**永远锁不住**。现在连续失败 5 次会真正进入 10 分钟锁定。

**6. 前端更"听话"**
待处理订单的自动发货定时器不会叠加触发；扫码登录成功后会立刻停止轮询，不会重复建号；商品同步失败后刷新按钮不会一直灰着；上传图片失败也不会留下后台定时器。

#### 升级方式

```bash
# 1. 备份数据库与旧版本
docker compose exec mysql mysqldump -uxianyusmart -p xianyusmart > backup-$(date +%F).sql
cp /opt/xianyuSmart/app.jar /opt/xianyuSmart/app.jar.bak

# 2. 替换并重启
cp xianyusmart-2.1.2.jar /opt/xianyuSmart/app.jar
docker compose -f /opt/xianyuSmart/compose.yaml restart app
```

镜像方式：`docker pull ghcr.io/evvvvvvvan/xianyusmart:v2.1.2`，改 `APP_IMAGE` 后 `docker compose up -d`。

> 注意：本次新增数据库迁移 `V19`（给运营任务加租约字段），首次启动会自动执行，请务必先备份。

#### 已知限制

- 多副本部署时，连接状态、风控熔断、人工接管缓存仍是进程内状态，扩容前需要额外的共享存储方案。
- 平台消息发送超时目前仍按"已发送"处理（否则会重复发送），下一版会拆出"已发送但未确认"的独立状态。
