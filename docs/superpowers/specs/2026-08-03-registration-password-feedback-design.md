# 注册密码强度与实时反馈设计

## 背景

当前注册页在账号为空、密码为空、两次密码不一致、账号长度不合格或密码长度不合格时直接结束提交，没有行内错误或提示。用户只能看到“创建账号”没有响应，无法判断注册失败原因。

后端注册接口目前仅校验密码长度为 8–72 位，前后端没有统一的弱密码判断。此次改动只覆盖公开注册流程，不扩展到登录、修改密码、管理员创建账号或重置密码页面。

## 密码规则

注册密码必须同时满足以下条件：

1. 长度为 8–72 位。
2. 至少包含字母、数字、符号中的两类。
3. 不能与账号相同，比较时忽略大小写和账号首尾空格。
4. 不能全部由同一个字符重复组成。
5. 不能使用常见弱密码：`12345678`、`password`、`password123`、`admin123`、`qwerty123`、`abc12345`、`11111111`、`00000000`，比较时忽略大小写。

字母指英文字母，数字指 `0-9`，除此之外的字符计入符号。密码保留原始内容，不自动去除首尾空格，也不静默截断。

## 强度等级

- **弱**：任一必填规则未满足，不允许注册。
- **中**：全部必填规则已满足，但长度小于 12 位或只包含两类字符，允许注册。
- **强**：全部必填规则已满足，长度至少 12 位，并同时包含字母、数字和符号，允许注册。

强度只用于帮助理解，不显示不可靠的熵值或“绝对安全”描述。

## 注册页交互

密码输入框下方实时展示：

- 三段式强度条和“弱 / 中 / 强”文字，不能只依赖颜色表达状态。
- “8–72 位字符”检查项。
- “至少包含字母、数字、符号中的两类”检查项。
- “不能与账号相同，也不能使用常见或重复弱密码”检查项。

确认密码输入后实时显示“密码一致”或“两次密码不一致”。账号为空或长度不在 3–20 位时显示对应行内错误。

“创建账号”按钮仅在账号、密码和确认密码全部有效时可用。按回车或点击提交时仍执行同一套前端校验，防止绕过按钮状态。后端失败继续使用现有全局错误提示，并保留服务端返回的具体原因。

页面沿用现有登录卡片、颜色和输入框样式，不增加弹窗、不引入新的 UI 或密码强度依赖。错误提示使用 `aria-live="polite"`，保证辅助技术可以感知实时变化。

## 后端兜底

注册接口在写入用户前执行与前端一致的密码规则，按固定顺序返回首个可操作错误：

1. `密码长度需在8-72之间`
2. `密码至少包含字母、数字、符号中的两类`
3. `密码不能与账号相同`
4. `密码过于简单，请更换后重试`

后端是最终安全边界；即使绕过前端，也不能提交弱密码。现有 BCrypt 存储、注册后自动登录、租户权限初始化和数据库结构均不改变。

## 验收范围

### 功能验证

- 空账号、短账号、空密码、短密码、超长密码、单一字符类型、常见密码、重复密码、账号同名密码和确认密码不一致均得到即时明确提示。
- 中等和强密码可以正常注册，成功后保持自动登录行为。
- 后端直接请求弱密码时返回明确校验信息，不创建用户。
- 登录页及注册与登录模式切换行为不回归。

### UI 验证

- 桌面端和 480px 移动端下，强度条、规则提示和按钮不溢出登录卡片。
- 弱、中、强状态同时具有颜色和文字差异。
- 显示密码、隐藏密码、回车提交和加载禁用状态正常。

### 工程验证

- Java 21 后端测试通过。
- Vue TypeScript 类型检查和 Vite 正式构建通过。
- 不新增数据库迁移、第三方依赖或临时测试产物。
