# 滑块任务卡死修复设计

## 背景与根因

生产环境账号 1 的全自动滑块任务长期停留在 `RUNNING`。容器进程和 JVM 线程栈确认：

- Playwright Chromium 和驱动已正常启动。
- 滑块任务线程阻塞在 `PlaywrightCaptchaBrowserRunner.findSlider` 的 `Locator.count()`。
- `PlaywrightManager.cleanTempFiles()` 会在服务启动 5 分钟后无条件删除 `playwright*` 临时目录，没有对目录应用 1 小时过期判断。
- 驱动目录在任务运行期间被删除后，Playwright Java 同步调用持续等待驱动响应，业务循环中的 5 分钟截止时间无法介入。
- 同账号已有活动任务时，后续不同模式请求会直接返回旧任务，导致人工模式看起来也一直处于自动模式的 `RUNNING`。

## 目标

1. 活跃 Playwright 临时目录不得被定时清理。
2. 滑块任务必须支持硬超时和主动取消，不得永久停留在 `PENDING` 或 `RUNNING`。
3. 自动模式显示浏览器启动、页面打开、滑块识别、拖动尝试和结果等待等阶段。
4. 不同模式不得静默复用旧任务。
5. 无桌面的生产容器选择人工模式时立即返回明确的 `UNSUPPORTED`。
6. Cookie、Token 和滑块地址不得出现在新增状态、接口响应或测试输出中。

## 非目标

- 不增加远程桌面、VNC 或浏览器流式画面。
- 不修改 MySQL、Nginx、Compose、Dockerfile 或 Playwright 版本。
- 不改变付款、固定内容、卡密和小刀订单发货链路。

## 方案

### 临时目录清理

`PlaywrightManager.cleanTempFiles()` 对文件和目录统一执行 1 小时过期判断。未达到阈值的 `playwright*`、Chromium、pipe 和 socket 路径全部跳过，只删除确认过期的临时产物。

### 可中断任务

`CaptchaSolveServiceImpl` 使用 `FutureTask` 保存每个账号的执行句柄，并复用现有调度器注册 5 分钟超时任务。

- 超时任务先把当前任务原子更新为 `TIMEOUT`，再调用 `Future.cancel(true)`。
- Playwright 1.40 的 `PipeTransport.poll()` 对线程中断会抛出异常，因此阻塞的同步调用可以退出。
- 完成、超时和取消统一通过一次性资源释放控制，避免重复释放浏览器并发许可。
- 旧任务结束时只有任务标识仍匹配且状态仍为活动态才允许写回结果，避免覆盖新任务。

### 主动取消与模式切换

新增取消能力和 `CANCELLED` 终态：

- 前端运行期间显示“取消验证”。
- 取消后中断执行线程并立即恢复模式选择。
- 同账号存在活动任务且请求模式不同，返回明确提示，要求先取消当前任务，不再返回旧模式任务。

### 阶段进度

`CaptchaBrowserRunner` 接收进度回调，服务只保存不含敏感信息的阶段文本：

1. 正在启动浏览器。
2. 正在打开验证页面。
3. 正在识别滑块。
4. 正在执行第 N/5 次自动拖动。
5. 已完成拖动，正在等待验证结果。
6. 人工模式等待本地浏览器操作。

前端继续每 2 秒轮询，同时显示任务已运行时间。终态停止轮询并恢复按钮。

### 人工模式

人工模式在进入 Playwright 启动前检查桌面环境。生产 Docker 无显示环境时直接返回 `UNSUPPORTED`，提示改用全自动或粘贴 Cookie。

## 验证闭环

### 临时失败测试

正式代码修改前创建并观察以下测试失败：

- 未满 1 小时的 Playwright 临时目录不会被删除。
- 超时调度会中断阻塞任务并保持 `TIMEOUT`，旧线程不能覆盖终态。
- 主动取消会中断任务并进入 `CANCELLED`。
- 不同模式活动任务不会被静默复用。
- 进度回调会更新当前任务，旧任务回调不会污染新任务。
- 无桌面环境的人工模式返回 `UNSUPPORTED`。

测试转绿后删除本次临时测试文件，并重新执行正式验证。

### 本地正式验证

- Java 21 Maven 测试与打包通过。
- 前端类型检查和生产构建通过。
- Git 差异只包含本次滑块修复。
- 日志和接口响应扫描不包含 Cookie、Token 或滑块地址。

### 生产验证

提交和部署仅在本地闭环全部通过后执行。部署后使用账号 1 的现有过期 Cookie，通过正常连接与滑块接口完成：

1. 触发滑块验证并确认待处理地址生成。
2. 全自动任务阶段消息持续推进，不再永久 `RUNNING`。
3. 自动成功时 Cookie 更新并恢复 WebSocket；平台未通过时必须在 5 分钟内进入明确失败或超时终态。
4. 人工模式在生产容器立即返回 `UNSUPPORTED`。
5. 取消任务后 Chromium、Playwright 驱动和业务线程退出。
6. 容器健康检查和公网 `/actuator/health` 均为 `UP`。

任何一项失败都停止交付，继续修复后重新执行完整闭环。
