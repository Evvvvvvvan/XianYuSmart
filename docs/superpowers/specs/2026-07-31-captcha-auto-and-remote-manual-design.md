# 滑块全自动闭环与服务器人工拖动设计

## 背景与根因

生产环境已经能够生成新的 `RGV587` 滑块验证地址，Playwright Chromium 也能在容器内启动，但当前两种处理方式都没有形成用户可用闭环：

1. 人工模式在 `PlaywrightCaptchaBrowserRunner` 启动浏览器前检查本机桌面环境。Docker 无桌面时直接返回 `UNSUPPORTED`，因此生产页面中的“人工拖动”入口必然不可用。
2. 自动模式只等待滑块按钮，没有独立识别“验证容器已出现但仍在加载”的状态。平台出现加载转圈、点击框体重试、刷新页面或连接中断提示时，会被归类为“未识别到可拖动滑块”。
3. 自动模式以成功标识或滑块消失作为浏览器阶段成功信号，最终虽然会尝试更新 Cookie 和重连，但前端没有单独展示平台凭证复验阶段，失败时也不能区分滑块未通过、Cookie Session 过期和平台仍要求验证。
4. 当前任务状态只展示文本阶段。人工模式没有浏览器画面，也没有从网页向服务器 Playwright 提交拖动轨迹的通道。

上游实现提供了以下可复用思路：

- `xianyu-pilot`：等待验证码容器稳定、处理失败重试框和刷新提示、从首页重新进入消息页、回收浏览器 Cookie。
- `xianyu-auto-reply`：验证成功必须结合新 `x5sec` 和后续接口复验，区分链接过期、Cookie 过期和平台拒绝。
- `goofish-cli`：令牌桶和 `RGV587` 熔断只保护平台写操作，不负责求解滑块，不能替代本次浏览器验证闭环。

## 目标

1. 全自动模式在生产 Docker 中完成“获取新挑战、打开页面、识别、拖动、回收 Cookie、平台复验、WebSocket 重连”闭环。
2. 人工模式在生产 Docker 中直接把服务器浏览器画面显示在当前管理后台弹窗内，用户在画面上拖动后由 Java Playwright 执行轨迹。
3. 自动与人工模式都持续展示真实阶段、尝试次数、用时、剩余时间和明确失败原因。
4. 自动失败后可以直接切换人工模式；人工完成后无需复制 Cookie，系统自动更新凭证并重连。
5. 不新增 Node 服务、VNC、远程桌面、数据库表或第三方求解依赖。
6. 不改变平台写操作限流、小刀订单、自动发货、自动回复和其他账号业务。

## 非目标

1. 不承诺第三方平台的每次自动验证都会被接受；平台拒绝自动轨迹时必须保留可用的人工闭环。
2. 不把 Cookie、Token、完整验证地址或浏览器页面持久化到日志、数据库或磁盘。
3. 不开放任意浏览器导航、键盘输入或通用远程控制能力。
4. 不修改现有 Cookie 粘贴入口。
5. 不接入收费远程求解服务。

## 方案选择

### 方案一：后台内嵌浏览器画面和拖动轨迹

采用。

Java Playwright 在服务器无头运行，浏览器工作线程定期生成低质量 JPEG 内存快照。前端在当前滑块弹窗中轮询快照并记录用户拖动轨迹，松开鼠标后一次性提交归一化轨迹。浏览器工作线程从队列读取轨迹并使用 Playwright `Mouse` 重放。

优点：

- 不依赖服务器桌面、VNC、额外端口或新容器。
- 继续复用当前账号、租户鉴权、Cookie 回收和重连逻辑。
- Playwright 对象始终只由创建它的工作线程操作。
- 接口只暴露当前验证页快照和受限拖动命令。

### 方案二：Xvfb 与 noVNC

不采用。需要新增图形服务、WebSocket 代理、访问鉴权、端口和镜像依赖，资源及维护成本高于本次需求。

### 方案三：第三方远程求解 API

不采用。需要把账号 Cookie 交给外部服务，并引入费用、可用性和凭据安全风险。

## 总体架构

### 浏览器任务线程

每个账号最多存在一个短生命周期 `BrowserProcessSession`。会话保存：

- 当前任务模式。
- 最新 JPEG 画面、视口宽高和更新时间。
- 有界人工拖动命令队列。
- 取消状态和 Playwright 驱动进程句柄。

Playwright `Browser`、`BrowserContext`、`Page` 和 `Mouse` 不放入控制器，也不由 HTTP 请求线程调用。人工画面由浏览器线程截图后写入会话快照；HTTP 线程只读取已生成的不可变字节数组。人工轨迹由 HTTP 线程校验后入队，再由浏览器线程重放。

### 任务服务

`CaptchaSolveService` 继续负责任务生命周期，并增加两个受限能力：

1. 读取当前人工任务的最新画面。
2. 向当前人工任务提交一次拖动轨迹。

调用前必须确认：

- 账号属于当前租户。
- 当前账号存在运行中的 `MANUAL_BROWSER` 任务。
- 任务已经进入等待人工阶段。
- 画面和轨迹属于同一浏览器会话。

### 前端弹窗

人工任务进入等待阶段后：

1. 显示服务器浏览器画面。
2. 每 600 至 800 毫秒获取一次新画面。
3. 用户按下并拖动时记录画面内坐标和相对时间。
4. 松开后把轨迹坐标归一化到 `0..1`，一次提交。
5. 浏览器线程重放后继续刷新画面和任务状态。
6. 平台通过后自动进入 Cookie 回收和重连阶段。

桌面端使用鼠标事件，移动端使用 Pointer Events，同一套轨迹格式处理。

## 全自动处理

### 挑战准备

1. 暂停同账号后台重连。
2. 清理旧验证等待状态。
3. 调用 Token 接口获取当前挑战。
4. Token 已恢复时直接进入重连。
5. 返回新挑战时只使用本次新地址，不复用历史地址。
6. Cookie Session 明确过期时停止自动求解并提示重新登录。

### 页面识别

浏览器分别识别：

- 验证容器。
- 滑块按钮。
- 滑块轨道。
- iframe 和嵌套 iframe。
- 加载转圈。
- “验证失败/点击重试”状态。
- “刷新页面/连接中断”状态。
- 登录页或登录入口。

验证容器存在但滑块按钮尚未加载时，任务阶段显示“等待滑块加载”，不立即报“未识别到滑块”。等待达到上限后返回“验证组件已出现，但滑块按钮未加载”。

### 自动拖动与重试

保留现有 Playwright `Mouse` 轨迹算法和最多五次限制。每次失败后：

1. 读取平台失败提示。
2. 能点击重试时先重置验证组件。
3. 平台要求刷新或当前会话进入失败态时关闭旧消息页。
4. 从闲鱼首页点击消息入口生成新验证会话。
5. 更新任务阶段后再执行下一次拖动。

不执行后台无限重试，也不通过高频请求碰运气。

### 成功确认

浏览器阶段完成后：

1. 回收闲鱼相关域的新 Cookie。
2. 校验账号标识 `unb` 存在。
3. 更新账号 Cookie。
4. 清理旧 Token 并重新调用平台 Token 接口。
5. Token 接口再次返回验证码时，任务判定为失败，显示“滑块操作完成，但平台仍要求验证”。
6. Token 获取成功后启动 WebSocket。
7. WebSocket 实际连接建立后才返回 `SUCCEEDED`。

Cookie 更新成功但平台复验或重连失败时，保留精确失败阶段，不显示“验证成功”。

## 人工拖动处理

人工模式不再以服务器是否存在桌面决定是否可用：

- 本地存在交互桌面时可以继续打开有头浏览器。
- Docker 或无桌面服务环境使用无头浏览器，并在后台弹窗显示内存快照。

浏览器线程每次循环执行：

1. 检查登录页和验证结果。
2. 处理一条待执行人工拖动轨迹。
3. 生成最新 JPEG 快照。
4. 更新“等待人工拖动”状态。
5. 平台通过后进入统一 Cookie 回收、平台复验和重连流程。

轨迹约束：

- 至少 2 个点，最多 200 个点。
- 坐标必须是有限数字且位于 `0..1`。
- 总持续时间限制在合理范围。
- 每个账号只接受当前任务的轨迹。
- 队列容量为 1，新轨迹不能无限堆积。

## 接口

继续使用：

- `POST /websocket/captcha/solve`
- `POST /websocket/captcha/status`
- `POST /websocket/captcha/cancel`

新增：

### 获取人工画面

`POST /websocket/captcha/manual/frame`

请求只包含 `xianyuAccountId`。响应包含：

- Base64 JPEG。
- 原始视口宽高。
- 画面版本和更新时间。

响应不包含 Cookie、Token、验证地址或页面 HTML。

### 提交人工轨迹

`POST /websocket/captcha/manual/drag`

请求包含：

- `xianyuAccountId`
- 画面版本
- 归一化轨迹点 `x`、`y`、`elapsedMs`

后端拒绝过期画面、越界坐标、过长轨迹、非人工任务和跨租户账号。

## 进度与错误

新增或细化以下阶段：

- `WAITING_CAPTCHA`
- `WAITING_SLIDER`
- `CLICKING_RETRY`
- `CAPTURING_MANUAL_FRAME`
- `REPLAYING_MANUAL_DRAG`
- `COLLECTING_COOKIE`
- `UPDATING_COOKIE`
- `VALIDATING_CREDENTIAL`
- `RECONNECTING`

每秒心跳继续更新用时和剩余时间。错误至少区分：

- 浏览器启动失败。
- 验证地址过期或跳转到不允许域名。
- Cookie Session 过期。
- 验证容器未出现。
- 验证容器出现但滑块未加载。
- 平台返回拖动失败。
- 人工画面暂未生成。
- 人工轨迹无效或已过期。
- Cookie 未更新或缺少账号标识。
- 平台复验仍要求滑块。
- WebSocket 重连失败。

日志只记录账号内部 ID、阶段、异常类型和脱敏原因。

## 安全与资源

1. 画面只保存在 JVM 内存，任务结束后立即释放。
2. 接口继续通过账号查询触发租户归属校验。
3. 画面响应禁用缓存，前端替换旧画面后释放旧数据。
4. 截图频率限制为每秒最多两次，JPEG 使用中低质量，控制 CPU、内存和网络消耗。
5. 人工轨迹使用有界队列，防止请求堆积。
6. 任务取消、超时和异常继续强制终止当前 Playwright 进程树。
7. 不扩大允许访问的验证域名。

## 测试与验收

### 临时失败测试

正式实现前创建临时测试，先确认以下行为在当前代码中失败：

- 无桌面人工模式不能进入等待人工阶段。
- 人工任务无法产生画面。
- 人工轨迹无法提交和重放。
- 验证容器加载中会被误报为未识别滑块。
- 平台复验再次要求滑块时无法返回精确原因。

临时测试转绿后全部删除，并重新执行正式项目验证。

### 本地验证

- Java 21 测试通过。
- 前端 TypeScript 检查和生产构建通过。
- 本地受控页面验证截图更新、坐标缩放和轨迹队列。
- 自动模式覆盖等待、拖动、重试、失败和复验阶段。
- 人工模式覆盖鼠标和触摸 Pointer Events。
- 日志、接口和构建产物扫描不包含 Cookie、Token 或完整验证地址。
- 工作区不保留临时测试、测试页面或截图。

### 生产闭环

使用当前生产账号的正常验证入口执行：

1. 触发新的平台滑块挑战。
2. 全自动任务实时推进全部阶段。
3. 自动成功时确认 Cookie 已更新、Token 已通过平台复验、WebSocket 已连接。
4. 自动未被平台接受时确认任务进入明确失败终态，不停留在处理中。
5. 切换人工模式，确认服务器浏览器画面出现在当前弹窗。
6. 在弹窗内完成拖动，确认画面、Cookie、Token 和 WebSocket 全部闭环。
7. 取消和超时后确认 Chromium、Playwright 驱动和任务线程退出。
8. 确认容器健康、无重启、无 OOM，公网页面和健康检查正常。

自动和人工任一入口未形成实际平台放行与 WebSocket 恢复闭环，都不能判定本次功能完成。
