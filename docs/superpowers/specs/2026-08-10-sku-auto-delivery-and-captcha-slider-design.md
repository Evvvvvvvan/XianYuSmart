# 多规格自动发货与滑块更新设计

## 背景与根因

自动发货已经保存 `skuId`，前端也存在规格选择器，但当前链路仍有四个缺口：

1. SKU 查询只按商品 ID 查询，没有账号条件，接口失败还会被前端静默当成无规格商品。
2. 保存配置只校验商品和卡密仓库归属，没有校验 SKU 是否属于当前账号和商品。
3. 查询指定 SKU 配置和订单发货在精确配置缺失时都会回退到无 SKU 配置，多规格商品可能因此发送错误卡密。
4. 前端只有 SKU 数量大于 1 时才进入规格配置模式，缺少加载、错误、未配置和未保存切换保护。

当前滑块实现已经具备任务状态、五次重试、iframe 查找、自动拖动、服务器人工画面、Cookie 回收和重连闭环，但自动和人工拖动仍通过 Playwright `Mouse` 发送。上游 `xianyu-pilot` 在 2026 年 8 月增加了 CDP 增量鼠标事件、三种轨迹轮换、浏览器指纹一致性、最小急动度轨迹、加载失败防误判和更完整的失败恢复。现有实现缺少这些关键变化，导致轨迹能够移动但平台不接受。

## 目标

1. 多规格商品可以按每个完整 SKU 组合独立配置固定内容或卡密发货。
2. SKU 查询、配置保存和订单发货始终保持账号与商品归属隔离。
3. 多规格订单只使用精确 SKU 配置，规格不明或未配置时停止发货，禁止错误回退。
4. 自动和人工滑块都使用带 `deltaX`、`deltaY` 的 CDP 鼠标事件。
5. 自动滑块轮换三种轨迹，并处理加载、失败、重试、刷新、连接中断和登录过期状态。
6. 自动模式五次失败后停止，并提供一键启动人工拖动和粘贴 Cookie 的入口。
7. 保持现有 Java 服务、任务状态、Cookie 更新、Token 复验和 WebSocket 重连架构，不新增 Node 服务或部署组件。

## 非目标

1. 不修改固定内容、卡密库存原子扣减、发货凭证、私聊和确认收货话术的既有业务规则。
2. 不新增数据库表，不迁移现有无 SKU 商品配置。
3. 不引入第三方滑块求解服务、VNC 或远程桌面。
4. 不承诺第三方平台每次接受自动轨迹；自动失败必须保留人工闭环。
5. 不在日志、数据库或磁盘保存 Cookie、Token、完整验证地址或滑块页面截图。

## 方案选择

### 方案一：在现有 Java Playwright 模块内移植关键更新

采用。

复用当前 `PlaywrightCaptchaBrowserRunner`、`CaptchaSolveService`、人工画面接口和前端弹窗，在现有模块内增加 CDP 鼠标、三种轨迹、状态判断和失败恢复。该方案改动集中，不增加运行时和部署边界。

### 方案二：完整引入上游 Node Crawler

不采用。需要新增 Node 服务、容器、内部鉴权、接口协议和重复的 Cookie 生命周期管理，维护成本高于当前需求。

### 方案三：只保留人工拖动

不采用。虽然实现最少，但不满足自动求解和上游功能同步需求。

## 多规格自动发货设计

### SKU 查询与归属

`GoodsSkuController` 的列表和详情接口增加 `xianyuAccountId` 参数。`GoodsSkuService` 增加按账号和商品查询、计数和精确 SKU 查询能力，所有查询同时包含：

- `xianyu_account_id`
- `xy_goods_id`
- 必要时包含 `sku_id`

前端从已选择账号传递账号 ID。接口返回失败时保留错误状态和重试入口，不把失败结果转换为空数组。

### 配置保存与查询

保存配置时继续校验账号、商品、固定模板和卡密仓库归属，并增加以下规则：

1. `skuId` 非空时必须存在于当前账号和当前商品的 SKU 列表。
2. `skuName` 使用数据库中的 `valueText`，不信任前端传入名称。
3. 指定 `skuId` 查询配置时只查询精确配置，不回退到无 SKU 配置。
4. 未指定 `skuId` 时继续查询无 SKU 配置，兼容无规格商品和历史数据。

现有 `(xianyu_account_id, xy_goods_id, sku_id)` 配置模型继续使用，不新增表和字段。

### 发货匹配

订单详情解析完成后按以下顺序选择配置：

1. 当前账号和商品没有 SKU 数据时，继续使用无 SKU 配置。
2. 当前账号和商品存在 SKU 数据时，订单必须解析出 `skuId`。
3. 订单 `skuId` 必须属于当前账号和商品。
4. 只查询该 `skuId` 的配置，不命中时停止发货。

失败原因至少区分：

- `订单规格未识别，已停止自动发货`
- `订单规格不存在或已失效，已停止自动发货`
- `当前规格未配置自动发货`

停止发货时不领取卡密、不发送凭证、不发送私聊，并继续通过现有订单记录和异常流程展示原因。

### 前端交互

商品选择完成后先加载 SKU，再加载对应配置。多规格区域展示：

- 完整规格组合名称。
- 价格和可用数量。
- 当前选中状态。
- 已配置或未配置状态。
- 已配置数量与规格总数。

长名称允许换行并提供完整标题，移动端使用可滚动或自动换行布局。SKU 加载中禁用保存；加载失败显示错误和重试按钮；SKU 缺少有效 ID 时显示数据异常并禁止保存。

切换账号、商品、规格或返回商品列表前比较当前表单与最近加载快照。存在未保存内容时使用确认提示，确认后切换，取消时保留当前编辑状态。

## 滑块更新设计

### CDP 鼠标

新增内部拖动鼠标抽象：

1. 优先通过 `BrowserContext.newCDPSession(Page)` 创建 CDP 会话。
2. 使用 `Input.dispatchMouseEvent` 发送 `mouseMoved`、`mousePressed` 和 `mouseReleased`。
3. 每个移动事件根据上一个坐标计算并携带 `deltaX`、`deltaY`。
4. `steps` 大于 1 时执行线性插值，每个插值点都携带正确增量。
5. CDP 创建失败时回退现有 Playwright `Mouse`，保证任务仍可运行。
6. 自动拖动和人工轨迹重放统一使用该抽象，避免人工模式继续受到相同问题影响。

### 三种轨迹

五次自动尝试按顺序轮换：

1. 容器内轨迹：多阶段速度、Y 轴弧线、停顿、微调和过冲回退。
2. 容器外轨迹：在拖动过程中加入较大的 Y 轴偏移，再回到正确终点。
3. 最小急动度轨迹：使用 `10t³ - 15t⁴ + 6t⁵` 位置曲线、100 至 140 个采样点、随机游走和短暂停顿。

每次拖动前增加有限的鼠标移动和阅读停顿。所有轨迹保持总任务超时和取消检查，不进行无限尝试。

### 浏览器环境与页面状态

在现有指纹脚本基础上补齐 Windows UA 一致性相关属性：

- `navigator.webdriver`
- `navigator.platform`
- `navigator.vendor`
- `navigator.appVersion`
- `navigator.userAgentData`
- `window.chrome`
- plugins、languages、permissions
- WebGL、hardwareConcurrency、deviceMemory

页面处理增加：

1. 识别 `chrome-error://` 和 `chromewebdata`，禁止把空页面判定为成功。
2. 识别 punish frame，但不把 Token API 名称误判为 Cookie 失效。
3. 等待验证容器和滑块稳定加载，避免加载转圈期间提前判定。
4. 只把明确失败选择器和短失败文案判定为失败，不把 `.nc-lang-cnt` 当作失败状态。
5. 支持点击框体重试、刷新或连接中断提示。
6. 会话失效时关闭旧消息页，从首页重新打开消息页。
7. 重试前只清理本轮风险临时 Cookie，保留登录所需 Cookie。
8. Cookie Session 过期时停止自动重试并提示重新登录。

浏览器阶段通过后仍必须执行现有 Cookie 更新、Token 复验和 WebSocket 重连。平台复验再次要求滑块时不能返回成功。

### 失败兜底 UI

自动模式最多尝试五次。任务进入 `FAILED`、`TIMEOUT` 或 `UNSUPPORTED` 后：

- 自动模式失败时显示“转人工拖动”按钮。
- 同时保留“粘贴 Cookie”入口。
- “转人工拖动”由操作人员点击后启动新的 `MANUAL_BROWSER` 任务，不自动启动人工任务。
- Cookie Session 过期提示优先引导重新登录或粘贴 Cookie。
- 执行中继续禁止重复启动，取消按钮继续终止浏览器进程和任务。

桌面端保持当前弹窗宽度；移动端按钮自动换行，人工画面保持比例，继续使用 Pointer Events 支持触控拖动。

## 错误处理与资源边界

1. 同账号同一时间只允许一个滑块任务。
2. 自动尝试上限为 5，总任务超时为 5 分钟。
3. CDP 会话、页面、浏览器和 Playwright 驱动在成功、失败、取消和超时后全部释放。
4. 人工轨迹继续限制点数、坐标范围、时长和画面版本。
5. SKU 加载失败时不允许按无规格商品保存配置。
6. SKU 精确配置未命中时不触发卡密库存操作。
7. 所有新增日志只记录内部账号 ID、商品 ID、SKU ID、阶段和脱敏原因。

## 测试与验收

### 临时失败测试

实现前创建临时测试并确认当前代码不能满足以下行为：

- SKU 查询按账号隔离。
- 非当前商品 SKU 不能保存配置。
- 指定 SKU 查询不能回退通用配置。
- 多规格订单 SKU 不明或未配置时不能发货。
- CDP 移动事件携带非零 `deltaX`、`deltaY`。
- 三种轨迹坐标、距离、步数和时长保持边界。
- 页面加载失败不能判定滑块成功。
- 人工轨迹使用与自动轨迹相同的 CDP 发送路径。
- 自动失败后前端能够一键启动人工任务。

临时测试转绿后全部删除，再执行正式项目验证。

### 本地验证

- Java 21 后端测试和构建通过。
- 前端 TypeScript 类型检查通过。
- 前端生产构建通过。
- 本地受控页面验证 CDP 鼠标增量、自动轨迹和人工轨迹重放。
- 检查桌面和移动端 SKU 区域、失败兜底按钮和人工画面布局。
- 扫描日志和构建产物，确认不包含 Cookie、Token、完整验证地址或持久化截图。
- 工作区不保留临时测试代码、测试页面、测试数据或截图。

### 验收边界

代码验证可以确认事件发送、状态机、配置隔离和 UI 行为，但不能替代真实平台挑战。没有真实账号触发的滑块时，不声明线上自动通过率。真实环境最终验收应确认：

1. 多规格商品能够逐项保存不同卡密仓库并按订单 SKU 正确发货。
2. 未配置规格不会领取或误发其他规格卡密。
3. 自动滑块成功后 Cookie、Token 和 WebSocket 全部恢复。
4. 自动五次失败后任务正常结束，并可一键进入人工拖动。
5. 人工拖动成功后复用同一凭证更新和重连闭环。
